## Overview

The YAML Engine provides bidirectional conversion between `Pipeline_State` (the internal JSON representation) and GitLab CI/CD YAML format. It handles parsing, generation, optimization, and validation.

## Interface

```typescript
interface YAML_Engine {
  toYAML(state: Pipeline_State): string;
  fromYAML(yaml: string): Pipeline_State;
  validateSyntax(yaml: string): ValidationResult;
  detectAnchors(state: Pipeline_State): AnchorMap;
  generateLayout(jobs: Record<string, Job_Node_Config>, stages: string[]): Record<string, NodePosition>;
}
```

## Methods

### toYAML()

Converts `Pipeline_State` to GitLab CI/CD YAML string.

<ParamField path="state" type="Pipeline_State" required>
  The pipeline state to convert
</ParamField>

<ResponseField name="return" type="string">
  Valid GitLab CI/CD YAML string
</ResponseField>

**Example:**

```typescript
import { yamlEngine } from './engine/yaml-engine';

const pipelineState: Pipeline_State = {
  version: '1.0',
  metadata: {
    created: '2024-01-01T00:00:00Z',
    modified: '2024-01-01T00:00:00Z'
  },
  global: {
    image: 'node:18'
  },
  stages: ['build', 'test'],
  jobs: {
    'job-1': {
      id: 'job-1',
      name: 'build',
      stage: 'build',
      script: ['npm install', 'npm run build']
    },
    'job-2': {
      id: 'job-2',
      name: 'test',
      stage: 'test',
      script: ['npm test'],
      needs: ['build']
    }
  },
  ui: {
    nodes: {
      'job-1': { x: 0, y: 0 },
      'job-2': { x: 300, y: 0 }
    },
    viewport: { x: 0, y: 0, zoom: 1 }
  }
};

const yaml = yamlEngine.toYAML(pipelineState);
console.log(yaml);
```

**Output:**

```yaml
image: node:18

stages:
  - build
  - test

build:
  stage: build
  script:
    - npm install
    - npm run build

test:
  stage: test
  script:
    - npm test
  needs:
    - build
```

**Behavior:**

- Removes `ui` metadata before conversion
- Generates anchors for repeated configuration
- Orders jobs by stage, then alphabetically
- Preserves all job configuration
- Handles special characters in strings

### fromYAML()

Parses GitLab CI/CD YAML string into `Pipeline_State`.

<ParamField path="yaml" type="string" required>
  Valid GitLab CI/CD YAML string
</ParamField>

<ResponseField name="return" type="Pipeline_State">
  Parsed pipeline state with generated UI metadata
</ResponseField>

**Example:**

```typescript
const yaml = `
image: node:18

stages:
  - build
  - test

build:
  stage: build
  script:
    - npm install
    - npm run build

test:
  stage: test
  script:
    - npm test
  needs:
    - build
`;

const pipelineState = yamlEngine.fromYAML(yaml);
console.log(pipelineState);
```

**Output:**

```typescript
{
  version: '1.0',
  metadata: {
    created: '2024-01-01T00:00:00Z',
    modified: '2024-01-01T00:00:00Z'
  },
  global: {
    image: 'node:18'
  },
  stages: ['build', 'test'],
  jobs: {
    'build': {
      id: 'build',
      name: 'build',
      stage: 'build',
      script: ['npm install', 'npm run build']
    },
    'test': {
      id: 'test',
      name: 'test',
      stage: 'test',
      script: ['npm test'],
      needs: ['build']
    }
  },
  ui: {
    nodes: {
      'build': { x: 0, y: 0 },
      'test': { x: 0, y: 200 }
    },
    viewport: { x: 0, y: 0, zoom: 1 }
  }
}
```

**Behavior:**

- Parses YAML using js-yaml library
- Extracts jobs, stages, and global config
- Generates unique IDs for jobs
- Applies auto-layout algorithm for node positions
- Resolves anchors and aliases automatically
- Throws `YAMLParseError` on syntax errors

**Error Handling:**

```typescript
try {
  const state = yamlEngine.fromYAML(invalidYaml);
} catch (error) {
  if (error instanceof YAMLParseError) {
    console.error(`Parse error at line ${error.line}, column ${error.column}`);
    console.error(error.message);
  }
}
```

### validateSyntax()

Validates YAML syntax without full parsing.

<ParamField path="yaml" type="string" required>
  YAML string to validate
</ParamField>

<ResponseField name="return" type="ValidationResult">
  Validation result with errors if any
</ResponseField>

**Example:**

```typescript
const yaml = `
build:
  stage: build
  script:
    - npm build
  invalid_key: [unclosed array
`;

const result = yamlEngine.validateSyntax(yaml);

if (!result.valid) {
  result.errors.forEach(error => {
    console.error(`Line ${error.line}: ${error.message}`);
  });
}
```

**Output:**

```typescript
{
  valid: false,
  errors: [
    {
      line: 5,
      column: 17,
      message: 'Unexpected end of stream'
    }
  ]
}
```

**Behavior:**

- Fast syntax-only validation
- Does not validate GitLab CI/CD schema
- Returns line and column numbers for errors
- Useful for pre-validation before parsing

### detectAnchors()

Detects repeated configuration blocks for anchor generation.

<ParamField path="state" type="Pipeline_State" required>
  Pipeline state to analyze
</ParamField>

<ResponseField name="return" type="AnchorMap">
  Map of anchor names to configuration and usage
</ResponseField>

**Example:**

```typescript
const pipelineState: Pipeline_State = {
  // ... metadata
  jobs: {
    'job-1': {
      id: 'job-1',
      name: 'build',
      stage: 'build',
      script: ['npm build'],
      cache: {
        key: '$CI_COMMIT_REF_SLUG',
        paths: ['node_modules/']
      }
    },
    'job-2': {
      id: 'job-2',
      name: 'test',
      stage: 'test',
      script: ['npm test'],
      cache: {
        key: '$CI_COMMIT_REF_SLUG',
        paths: ['node_modules/']
      }
    }
  },
  // ... ui
};

const anchors = yamlEngine.detectAnchors(pipelineState);
console.log(anchors);
```

**Output:**

```typescript
{
  'cache_0': {
    config: {
      key: '$CI_COMMIT_REF_SLUG',
      paths: ['node_modules/']
    },
    usedBy: ['job-1', 'job-2']
  }
}
```

**Behavior:**

- Compares configuration blocks using JSON stringification
- Only creates anchors for blocks used by 2+ jobs
- Generates sequential anchor names (cache_0, cache_1, etc.)
- Supports cache, variables, before_script, after_script

### generateLayout()

Generates node positions using auto-layout algorithm.

<ParamField path="jobs" type="Record<string, Job_Node_Config>" required>
  Jobs to position
</ParamField>

<ParamField path="stages" type="string[]" required>
  Ordered list of stages
</ParamField>

<ResponseField name="return" type="Record<string, NodePosition>">
  Map of job IDs to positions
</ResponseField>

**Example:**

```typescript
const jobs = {
  'build': {
    id: 'build',
    name: 'build',
    stage: 'build',
    script: ['npm build']
  },
  'test:unit': {
    id: 'test:unit',
    name: 'test:unit',
    stage: 'test',
    script: ['npm test:unit']
  },
  'test:e2e': {
    id: 'test:e2e',
    name: 'test:e2e',
    stage: 'test',
    script: ['npm test:e2e']
  }
};

const stages = ['build', 'test'];

const positions = yamlEngine.generateLayout(jobs, stages);
console.log(positions);
```

**Output:**

```typescript
{
  'build': { x: 0, y: 0 },
  'test:unit': { x: 0, y: 200 },
  'test:e2e': { x: 250, y: 200 }
}
```

**Behavior:**

- Groups jobs by stage
- Positions stages vertically (200px spacing)
- Positions jobs within stage horizontally (250px spacing)
- Centers single jobs in their stage
- Handles missing stages gracefully

## Types

### Pipeline_State

```typescript
interface Pipeline_State {
  version: string;
  metadata: {
    created: string;
    modified: string;
    name?: string;
  };
  global: {
    image?: string;
    variables?: Record<string, string | Variable>;
    cache?: CacheConfig;
    before_script?: string[];
    after_script?: string[];
  };
  stages: string[];
  jobs: Record<string, Job_Node_Config>;
  ui: {
    nodes: Record<string, NodePosition>;
    viewport: { x: number; y: number; zoom: number };
  };
}
```

### ValidationResult

```typescript
interface ValidationResult {
  valid: boolean;
  errors: Array<{
    line?: number;
    column?: number;
    message: string;
  }>;
}
```

### AnchorMap

```typescript
interface AnchorMap {
  [anchorName: string]: {
    config: any;
    usedBy: string[];
  };
}
```

### NodePosition

```typescript
interface NodePosition {
  x: number;
  y: number;
}
```

## Error Handling

### YAMLParseError

Thrown when YAML parsing fails:

```typescript
class YAMLParseError extends Error {
  line: number;
  column: number;
  snippet: string;
}
```

**Example:**

```typescript
try {
  const state = yamlEngine.fromYAML(invalidYaml);
} catch (error) {
  if (error instanceof YAMLParseError) {
    console.error(`Parse error at line ${error.line}, column ${error.column}`);
    console.error(`Snippet: ${error.snippet}`);
    console.error(error.message);
  }
}
```

## Best Practices

<AccordionGroup>
  <Accordion title="Always Validate Before Parsing" icon="check">
    Use `validateSyntax()` before `fromYAML()` to provide better error messages:
    
    ```typescript
    const validation = yamlEngine.validateSyntax(yaml);
    if (!validation.valid) {
      // Show errors to user
      return;
    }
    const state = yamlEngine.fromYAML(yaml);
    ```
  </Accordion>
  
  <Accordion title="Memoize YAML Generation" icon="bolt">
    YAML generation can be expensive for large pipelines. Use `useMemo`:
    
    ```typescript
    const yaml = useMemo(() => {
      return yamlEngine.toYAML(pipelineState);
    }, [pipelineState]);
    ```
  </Accordion>
  
  <Accordion title="Handle Errors Gracefully" icon="triangle-exclamation">
    Always wrap YAML operations in try-catch:
    
    ```typescript
    try {
      const state = yamlEngine.fromYAML(yaml);
    } catch (error) {
      // Show user-friendly error message
      showError('Failed to parse YAML. Please check syntax.');
    }
    ```
  </Accordion>
</AccordionGroup>
